# 安全与授权规则：最小权限、秘密不落库、绝不触碰交易账户

> 最后更新：2026-07-22 ｜ 适用：外部 SDK/API、账户、凭证、通知、LLM、依赖和发布

## 硬规则（违反按 review P1；交易/凭证泄露按 P0）

| 规则 | 为什么 |
| --- | --- |
| 禁止读取交易密码、连接交易账户、读取持仓或调用下单接口 | 这是产品锁定安全边界，越界可能直接造成资金风险 |
| SDK、Bark 与其他密钥正式运行只放 Windows Credential Manager / macOS Keychain；环境变量仅用于显式开发测试；不得进入 Git、配置、普通日志、数据库和导出 | Git 历史和备份会让一次误提交长期扩散 |
| 数据供应商、公式、历史保存和结果展示必须在授权范围内；授权不明则功能关闭 | “能调用”不等于“被许可使用” |
| 未经业务负责人确认，不把完整行情、内部候选、反馈或日志发送给外部 LLM/服务 | 内部使用数据可能含商业与个人信息 |
| 外部通知只发送标题和三行最小候选信息，不发送详细特征、密钥或内部日志 | 减少第三方通道的数据暴露面 |
| 新依赖说明用途、许可证和安全影响，并锁定可复现版本 | 金融数据桌面应用的供应链需要可审计、可回滚 |

## 默认做法

- 使用最小权限账号；日志对路径、token、账号标识做脱敏。
- UI 凭据输入默认隐藏；新值先在内存测试，成功且 Human Owner 确认后原子替换，失败保留旧值。
- HTTP TLS 验证不得关闭；系统代理使用行为由 profile 明确配置。
- `.env`、`config/user.yaml`、数据库、缓存和日志由 `.gitignore` 阻止入库，提交前仍需人工 review。
- 依赖或 SDK 升级作为独立 PR，先回放和现场 smoke，再进入正常运行配置。

## 反例

- 为了“以后可能用”安装券商交易 SDK → 正确：不引入与候选观察无关的交易能力。
- 把 token 放进 `config.example.yaml` → 正确：只写环境变量名和占位符。

## 例外

- 无。自动交易与交易凭证边界不是可审批例外；如产品方向改变，必须另立项目/规格并做独立安全审查。
