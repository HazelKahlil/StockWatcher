# 排名规则：候选计算必须确定、可回放且尊重锁定边界

> 最后更新：2026-07-22 ｜ 适用：universe、price、sector、fund、trend3d、ranking、alert_policy、replay

## 硬规则（违反按 review P1；自动交易/未来泄漏按 P0）

| 规则 | 为什么 |
| --- | --- |
| 盘中候选只由确定性规则和版本化配置产生，LLM 不进入实时决策 | 同一输入必须得到同一结果，且能向用户解释 |
| 数据健康时可见批次固定三只；完整信号不足可用“近”补足并标整体偏弱；核心数据中断时不伪造三只 | 同时满足固定输出与异常安全这两个锁定要求 |
| “强/中”必须有板块通过；价格很强但板块弱最多为“近” | 防止把孤立上涨误报为共振候选 |
| 股票池必须排除 ST/*ST、退市整理、停牌、一字涨停、数据不完整的新股/复牌/除权当日等锁定项 | 保持业务口径和机械跳变安全边界 |
| 所有评分、阈值、权重、惩罚和配置版本随候选快照保存 | 用户反馈、回放和回滚需要知道当时规则 |
| 回放只能使用当时可获得的数据和当时有效的板块成分 | 未来泄漏会制造虚假的策略效果 |
| 去重、同股 5 分钟冷却、三四名替换门槛和盘中每日 3 批上限必须有边界测试 | “少打扰”是核心业务要求，不是 UI 微调 |

## 默认做法

- 今天、昨天、前天按配置权重计算，实际交易日而非自然日。
- 特征计算与提醒策略分离：主窗口可更新，弹窗是否发出由独立状态机决定。
- 每个规则变更先走 Replay/Synthetic，真实影子运行通过后再提升配置版本。

## 反例

- 用当日收盘后已知的最高价决定 10:00 候选 → 正确：只读取 10:00 前数据。
- 第三、第四名每秒互换就弹窗 → 正确：分差与连续周期达到替换门槛后再发。

## 例外

- 自动软参数优化只有达到样本门槛、收盘后运行、影子验证和可回滚时才可启用；硬规则永不自动调整。
