# UI 与通知规则：低打扰、可解释，失败不阻塞主链路

> 最后更新：2026-08-12 ｜ 适用：PySide6 主窗口、弹窗、Web 提醒、托盘、声音、iPhone 通道

## 硬规则（违反按 review P1）

| 规则 | 为什么 |
| --- | --- |
| 弹窗每批同一窗口三行，右下角、不抢焦点、轻声音、手动关闭 | 交易员持续看盘，提醒不能遮挡或抢操作 |
| 每行只显示名称、代码、当前涨幅和“强/中/近”；价格与长解释进详情 | 保持极简，同时保留可追溯入口 |
| 健康状态、最后更新时间、通达信连接和交易阶段始终可见 | 用户必须能区分“无信号”和“数据坏了” |
| 使用“候选/观察/强中近”，禁止“买入/卖出/胜率/模型置信度”等误导表达 | 工具不是交易建议或收益承诺 |
| 桌面先发，手机异步；手机超时/失败只降级并记录，不阻塞桌面 | iPhone 是辅助通道，不是核心依赖 |
| 手机密钥不显示在普通日志，不写仓库或明文数据库 | 防止通知通道被滥用和凭证泄露 |

## 默认做法

- 多屏位置、DPI、Windows 通知行为和安装后自启动必须在目标机手工验收。
- 主窗口 Top 20 默认折叠；复杂特征和分数放详情，不增加弹窗噪声。
- NotificationChannel 保持可替换，Bark 只是首选实现。

## 反例

- 三只股票各弹一个窗口 → 正确：一个批次、一个窗口、三行。
- iPhone 请求卡住 UI 线程 → 正确：桌面事件先提交，推送异步且有短超时。

## 例外

- 通达信跳转可作为后续开关；核心版本不得依赖它，默认复制代码或打开内部详情。
- 2026-08-11 Human Owner 明确授权“次日同点复盘”页展示历史理论收益与胜率；该例外仅限
  正式固定候选的可验证复盘，不改变普通候选/提醒文案，且页面必须固定声明未计手续费、
  滑点及实际成交限制、不构成投资建议。上涨红、下跌绿、待结算/不可用灰。
- 历史回补没有持久化状态时必须显示“待确认”，只有明确 `completed` 才可声称已回补；
  `running/partial/failed` 分别显示真实进度。数据库保留原始 `safe_reason`，普通 UI
  只展示简洁中文映射，不直接暴露内部异常标识。
- 2026-08-12 Human Owner 明确要求 Web 自动提醒更醒目：仅 Web 的强异动与固定
  09:45/14:45 使用居中 `alertdialog` 和轻遮罩，必须手动关闭并支持 Esc、焦点恢复和
  `prefers-reduced-motion`；桌面 PySide6 仍保持右下角、不抢焦点。手动抓取成功不得弹中央窗。
